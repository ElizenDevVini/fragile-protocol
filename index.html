Your AI agent needs money to work.
Right now it either has all of yours — or none.

Fragile is the cage in between.

Lock in a budget. Set who it can pay. Set when it expires. After that, the rules live on-chain. If the agent tries to go over — it can't. The transaction fails. Not "gets flagged." Not "sends you an email." Can't.

  • 01 Max spend per transaction.

Write them. Deploy. Walk away. The agent can't talk its way around them — neither can you, without starting a new cage from scratch.

SDK

Three lines.
That's the whole thing.

import { createFragile } from '@fragile/sdk'

// point at your cage, hand it the session key
const fragile = createFragile({ cage: '0x…', sessionKey: key, chain: base })

// agent pays — chain checks the rules, not you
await fragile.pay({ to: '0xRecipient', amount: '0.01 ETH' })

// or just say it
await fragile.intent('spend up to 0.1 ETH on Uniswap for 24h')

Audit & control

It writes
everything down.

Every payment. Every rejection. Every time the agent hit the ceiling and bounced. The log is on the contract — you didn't have to be awake for it.

On-chain events

Payments and rejections are contract events. Permanent. Nobody edits them after the fact.

Hard limits

No admin bypass. No override flag. The contract says no and that is the end of it.

Kill switch

One call to deactivate(). Budget zeroes out. Agent stops. No waiting on anyone.

Session keys

The agent never touches your private key. It gets a short-lived key scoped to the cage — nothing else.
